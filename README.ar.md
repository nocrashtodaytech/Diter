# Diter

**أداة واحدة لثلاثة أنظمة. صانع وسائط USB قابلة للإقلاع متعدد المنصات — ولن يلمس قرص النظام أبدًا.**

Diter هو أداة متعددة المنصات لإنشاء وسائط USB قابلة للإقلاع. على عكس الأدوات
التي «لا تكتب إلا نصف ما يخصها»، يوجّه Diter الاستراتيجية الصحيحة لكل صورة، بحيث
يتحوّل ISO ويندوز ومثبّت macOS وأي توزيعة Linux إلى قرص **قابل للإقلاع فعليًا** —
مع إبقاء قرص النظام خارج نطاق الاختيار.

## لماذا Diter

| الأداة | القصور |
|---|---|
| **Rufus** | ممتاز على ويندوز، لكنه لا يستطيع كتابة macOS (لا يدعم كتابة HFS/APFS) |
| **createinstallmedia** | مخصّص لـ Apple والمثبّتات فقط |
| **Etcher** | يعتمد `dd` في كل مكان، لكن ISO ويندوز ليس صورة هجينة، لذا ينتج قرصًا **غير قابل للإقلاع** |

يوجّه Diter كل صورة إلى المحرّك المناسب بدلًا من `dd` العشوائي:

| الهدف | الاستراتيجية |
|---|---|
| **ISO ويندوز** | تقسيم → FAT32 → نسخ الملفات → كود الإقلاع (تقسيم تلقائي لـ `install.wim > 4GB` عبر wimlib) |
| **macOS** | ثلاث مستويات: `createinstallmedia` → `asr` → `raw`، تغطي من 10.10 حتى الأحدث |
| **لينكس** | كتابة على مستوى البايت للقرص كاملًا، مع قسم `casper-rw` اختياري للحفظ الدائم |

## أبرز المزايا

- **متعدد المنصات** — يعمل على أجهزة macOS وويندوز ولينكس
- **تعرّف الصور** — يقرأ ترويسات الملفات مباشرة (ISO9660, GPT, MBR, HFS+, APFS, UDF, DMG) ويعرض سلسلة الأدلة
- **حماية قرص النظام** — ثلاث بوابات مستقلة؛ لا يمكن حتى اختيار قرص النظام
- **مساعد الصلاحيات** — تعمل المصادقة عبر مساعد خلفي بلا واجهة، فلا يُعاد تشغيل النافذة الرئيسية ولا تُفقد اختياراتك
- **تحقق بعد الكتابة** — إعادة قراءة القرص كاملًا ومقارنة SHA-256
- **المظهر** — فاتح / داكن / تلقائي (النظام)
- **تعدد اللغات** — 6 لغات: 简体中文, 繁體中文, English, 한국어, العربية, Русский

## نموذج الأمان

1. **التعداد** — يُحسب `verdict` لكل جهاز، وتُستبعد الأجهزة المقفلة من قائمة الاختيار
2. **التأكيد** — مربع اختيار + ضغط مطوّل لمدّة 1.5 ثانية
3. **قبل الكتابة** — إعادة التعداد ومقارنة السعة وإعادة تشغيل `assertWritable()`

على macOS، يعدّ فحص قرص النظام غير بديهي: المجلد الجذري `/` موجود على حاوية APFS
*مُصنّعة*، لذا يتعقّب الكود `APFSPhysicalStores` وصولًا إلى القرص الفعلي لتجنّب
النتائج الخاطئة. تم التحقق منه على أجهزة حقيقية.

## البدء (للتطوير)

```bash
npm install          # التثبيت الأول ينزّل بيئة تشغيل Electron
npm run preview      # بناء معاينة الواجهة فقط (بدون الحاجة إلى Electron)
npm start            # البناء وتشغيل تطبيق سطح المكتب
```

معاينة الواجهة (`preview/diter-preview.html`) عبارة عن ملف واحد مستقل يعتمد على
بيانات تجريبية — ولا يلمس قرصًا حقيقيًا أبدًا.

## النسخ الجاهزة (`release/`)

| النسخة | المنصة | ملاحظة |
|---|---|---|
| `Diter-1.0.2-mac-x64.dmg` | macOS (x64) | غير موقّعة — عند التشغيل الأول تحتاج إلى نقرة يمنى ← فتح |
| `Diter-1.0.2-win-x64.zip` | ويندوز (x64) | نسخة محمولة بدون مثبّت (احتفظ بالمجلد كاملًا) |

إعادة البناء: `npm run package` (انظر `build/package.sh`).

> **ملاحظة لويندوز**: إذا ظهرت رسالة «VCRUNTIME140_1.dll / MSVCP140.dll مفقود،
> جرّب إعادة التثبيت» عند تشغيل `Diter.exe`، فهذا يعني أن النظام يفتقر إلى حزمة
> Microsoft Visual C++ 2015–2022 القابلة لإعادة التوزيع (المطلوبة لتطبيقات
> Electron). شغّل `vc_redist.x64.exe` المرفق ثم أعد فتح Diter.

## بنية المشروع

```

docs/              ARCHITECTURE.md — التصميم الكامل ومصفوفة التوافق والمبرّرات
preview/           معاينات الواجهة ولقطات سير العمل
tools/             أدوات مساعدة للبناء والتغليف
```

تفاصيل التصميم الكاملة: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## التقنيات المستخدمة

Electron 33 · React 18 · esbuild — مع استدعاءات نظام Node خالصة (بلا اعتماديات
Rust/Go أصلية تحتاج إلى ترجمة).

## الحالة وخارطة الطريق

أُنجز: تعرّف الصور، تقييمات سلامة الأقراص، محرّكات الكتابة، الواجهة الكاملة وسير
العمل، مساعد الصلاحيات، التحقق.

مخطط له: تضمين `wimlib`/`ms-sys` في الحزمة؛ نقل مساعد macOS إلى `SMJobBless`؛
قفل وحدات تخزين ويندوز (`FSCTL_LOCK_VOLUME`).
